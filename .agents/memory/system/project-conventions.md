## Commit Conventions

**Format**: Conventional Commits (v1.0.0)
```
<type>[optional scope]: <description>

[optional body]

[optional footer]
```

**Types**: feat, fix, build, chore, ci, docs, style, refactor, perf, test

**Scopes**: api-types, client, server, mobile, storybook, ui, workspace

**Examples**:
- `feat(client): add search filters with Redis caching`
- `fix(mobile): refine RTL sorting logic in TagsCarousel`
- `chore(workspace): add staging build scripts`

## Branch Naming

**Patterns observed**:
1. **Linear tickets**: `name/RI-1234-short-description` (most common)
   - Example: `jeremie/ri-1055-afficher-la-source-rco-de-la-fiche`
   - Example: `luis/ri-1042-sur-android-si-je-swipe-dans-longlet-explorer-ca-fait`

2. **Type prefix**: `feat/feature-name`, `fix/bug-name`, `docs/doc-name`
   - Example: `feat/biome-migration`
   - Example: `fix/404-and-theme-regressions`

3. **Numbered**: `001-feature-name` (generated by .specify workflow)

## Code Style

**Biome Configuration** (replaced Prettier/ESLint):
- **Line width**: 100 characters
- **Indentation**: 2 spaces
- **Quotes**: Double quotes for strings
- **Imports**: Auto-organized
- Many rules disabled (noExplicitAny, a11y rules) - pragmatic approach for legacy code

**Import Patterns**:
```typescript
// ✅ Use ~ alias for lib imports
import { searchHelpers } from "~/lib/search-helpers";

// ✅ Group: external, internal, relative
import React from "react";
import { Button } from "@refugies-info/ui";
import { useSearch } from "~/hooks/useSearch";
import { SearchForm } from "./SearchForm";
```

**Styling Approach**:
- Tailwind CSS preferred for new features
- SCSS still present (legacy)
- Always use DSFR tokens/components as base
- No arbitrary values outside DSFR tokens

## Pull Request Process

1. Create feature branch from `dev`
2. Keep changes focused (avoid unrelated refactoring)
3. Run tests: `pnpm test`
4. Run linting: `pnpm lint`
5. Type check: `pnpm check:types`
6. Commit with Conventional Commits
7. Create PR against `dev`
8. **Accessibility review required** for user-facing changes
9. Merge with squash merge

## Pre-commit Hooks (Husky)

**Automatic checks on commit**:
- `biome check --write` on JS/TS files (auto-formats)
- `stylelint --fix` on CSS/SCSS files
- `knip` - detects unused files/exports

**Bypass** (use sparingly): `git commit --no-verify`
