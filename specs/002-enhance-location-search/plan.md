# Implementation Plan: Enhance Location Search UX

**Branch**: `001-enhance-location-search` | **Date**: 2025-10-28 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-enhance-location-search/spec.md`

## Summary

Enhance the location search UX in the recherche (search) page by enabling users to find cities and departments quickly. The implementation uses a dual-API approach: keep the existing `data.geopf.fr` municipality search and add `geo.api.gouv.fr` for department search. Results are merged into a single auto-suggest list (max 5 items) with clear visual distinction. The default filter label changes from "Département" to "Ville" to better reflect user expectations. Final filter remains stored as department code in the URL for backward compatibility.

## Key Decisions

1. **Dual API Approach**: Use two separate API calls (data.geopf.fr + geo.api.gouv.fr) rather than a single unified endpoint. Rationale: Leverages existing proven municipality API; geo.api.gouv.fr is the official French government department API.

2. **Result Merging**: Merge results client-side after both API calls complete. Rationale: Simpler than backend aggregation; maintains independence of data sources; enables local filtering/sorting.

3. **Visual Distinction**: Use labels or styling to distinguish city vs. department results. Rationale: Prevents user confusion when both match the search term (e.g., "Paris").

4. **Backward Compatibility**: Final filter remains department code in URL. Rationale: Maintains existing search functionality and bookmarkable URLs.

5. **No Backend Changes**: All changes client-side only. Rationale: Reduces deployment complexity; no API versioning needed; faster iteration.
